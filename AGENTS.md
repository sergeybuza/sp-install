# Инструкции для агентов

## Контекст проекта

- Проект предназначен для подготовки и проверки установки Смарт Платформы на промышленные ПК с Ubuntu Linux, подключённые по локальной сети.
- По вводным владельца, Смарт Платформа — глубокий форк ThingsBoard (TB), поставляемый в виде Docker-образов.
- Руководство пользователя и черновик инструкции будут предоставлены отдельно; в них возможны ошибки. Наличие утверждения в руководстве не подтверждает его фактическую работоспособность.
- Общайся и веди документацию на русском языке, если пользователь не попросил иначе.

## Правила работы с платформой

- Не считай поведение, конфигурацию, API, схему данных и процедуры ThingsBoard совместимыми с этим форком без подтверждения по материалам поставки или результатам проверки.
- Сохраняй полученные образы в `input/images/`, руководства и черновики — в `input/docs/` без редактирования оригиналов. Замечания, исправления и результаты проверок веди отдельно в `docs/review/`; согласованную и проверенную инструкцию — в `docs/installation/`.
- Описания целевых ПК веди в `inventory/hosts/`, состав и идентификаторы поставок — в `inventory/releases/`.
- Для замечания к документу указывай исходный файл, версию при наличии, раздел или страницу, проблему и основание для исправления. Непроверенные утверждения явно помечай.
- До подготовки исполняемой установки выясни версии Ubuntu, Docker и Compose, архитектуру ПК и образов, состав сервисов, теги или дайджесты, порты, тома, зависимости и необходимые ресурсы. Не подставляй вымышленные значения.
- До запуска скриптов и команд проверяй, какие пути, данные и сервисы они затрагивают. Подготовка файлов для целевого ПК не разрешает менять настройки текущего компьютера.
- Размещай скрипты рабочего компьютера в `scripts/local/`, скрипты целевого ПК — в `scripts/remote/`, проверки — в `scripts/checks/`. В инструкциях явно указывай место выполнения команды и целевой узел.
- Результаты отдельных запусков сохраняй локально в `reports/` с указанием ПК и времени запуска. Подтверждённые выводы переноси в документацию без секретов и рабочих данных.
- Не добавляй в Git секреты, рабочие `.env`, закрытые ключи, архивы образов, рабочие данные платформы, логи и резервные копии. Используй шаблоны без секретов; перед коммитом проверяй состав изменений.
- Записывай фактически выполненные проверки, окружение и их результаты. Проверка на машине разработки не подтверждает установку на целевом промышленном ПК.
