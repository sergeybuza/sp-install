# Установка Смарт Платформы

Проект для подготовки и проверки установки Смарт Платформы на промышленный ПК с Ubuntu Linux, подключённый по локальной сети. Смарт Платформа — глубокий форк ThingsBoard (TB).

На входе — Docker-образы и черновая документация поставщика. Полученные документы могут содержать ошибки; проверенные процедуры ведутся отдельно. Рабочий компьютер с этим проектом и целевой промышленный ПК — разные машины.

## Структура

| Путь | Назначение |
| --- | --- |
| `AGENTS.md` | Контекст проекта и правила работы с платформой |
| `input/images/` | Полученные файлы Docker-образов; образы исключены из Git |
| `input/docs/` | Оригиналы руководств, черновиков и сопроводительных документов |
| `docs/review/` | Замечания к исходным материалам, вопросы и результаты проверок |
| `docs/installation/` | Проверенная инструкция установки, обновления, восстановления и диагностики |
| `inventory/hosts/` | Описания целевых ПК: адрес в локальной сети, способ доступа, оборудование, ОС |
| `inventory/releases/` | Состав поставок: образы, версии, архитектуры, дайджесты и контрольные суммы |
| `deploy/compose/` | Файлы Docker Compose, когда будет подтверждён состав сервисов |
| `deploy/config/` | Шаблоны конфигурации без паролей и ключей |
| `scripts/local/` | Скрипты для рабочего компьютера: подготовка поставки, передача файлов и управление установкой |
| `scripts/remote/` | Скрипты для выполнения на целевом промышленном ПК |
| `scripts/checks/` | Проверки готовности окружения и работоспособности платформы |
| `reports/` | Локальные результаты запусков и диагностики по каждому ПК; отчёты исключены из Git |

## Порядок работы

1. Положить образы в `input/images/`, документы — в `input/docs/`, сохраняя оригиналы и сведения об их версии и происхождении.
2. Описать целевой ПК в `inventory/hosts/`, состав поставки — в `inventory/releases/`.
3. Проверить черновик инструкции. Вопросы и ошибки записать в `docs/review/` со ссылками на документ, раздел или страницу.
4. По подтверждённым требованиям подготовить конфигурацию в `deploy/` и необходимые скрипты в `scripts/`.
5. Проверить доступ к целевому ПК, подготовить окружение и передать необходимую поставку по локальной сети. Для каждой команды обозначать место выполнения: рабочий компьютер или целевой ПК.
6. Выполнить установку и проверки на целевом ПК. Результаты запуска сохранить в `reports/`, подтверждённую процедуру и обезличенные выводы — в `docs/installation/` и `docs/review/`.

Пока не предоставлены поставка, документы, параметры ПК и способ удалённого доступа. Версии Ubuntu и Docker, архитектура образов, состав сервисов, порты, тома и требования к ресурсам не подтверждены. Готовой конфигурации развёртывания и установочных скриптов пока нет.

## Работа с материалами

- Не переносить требования и команды ThingsBoard на Смарт Платформу без проверки.
- Отделять утверждения из руководства от результатов фактического запуска.
- Не хранить в Git пароли, токены, закрытые ключи, рабочие `.env`, данные платформы, резервные копии и архивы образов. Публичные шаблоны окружения называть `.env.example`.
- Перед добавлением материалов в Git проверять их на секреты и персональные данные. `.gitignore` не заменяет такую проверку.
