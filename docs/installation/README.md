# Инструкция установки

[Локальный MCP Смарт Платформы 1.0.0](sp-mcp-local.md) описывает проверенный запуск ARM64-контейнера на Mac, чтение числа устройств и подключение клиентов Codex/Claude Code. Границы проверки клиентов указаны отдельно.

Для стенда `192.168.10.107` восстановлена и затем выполнена после очистки [подготовка Docker на Ubuntu 26.04](ubuntu-26-docker.md). Повторное развёртывание 2026-11-12 завершено; [результаты и границы проверок](../review/2026-11-12-redeployment.md) описаны отдельно. Для повторения процедуры подготовлен [скилл sp-deploy](../../.agents/skills/sp-deploy/SKILL.md).

[Инструкция установки Смарт Платформы 2.0.0](smart-platform-2.0.0.md) описывает фактически развёрнутый монолит на стенде: PostgreSQL, Mosquitto, ядро и UI. Проверены одноразовая инициализация БД, UI/API, MQTT/TLS и повторный запуск. [Состав поставки](../../inventory/releases/smart-platform-2.0.0.md) и [исправления исходных документов](../review/2026-11-12-installation-documents.md) ведутся отдельно. Границы выполненных проверок указаны в инструкции.

[Highload на Mac](highload-mac.md) — проверенный 2026-11-14 пробный поток
на отдельный стенд: три контейнера, стандартный Excel-сценарий, передача
токена из окружения без записи в конфигурационный файл и команда остановки.

По мере проверки документируйте:

1. Требования к оборудованию и поддерживаемые версии Ubuntu, Docker и Compose.
2. Доступ к ПК по локальной сети и подготовку окружения.
3. Передачу поставки, загрузку образов, конфигурацию сервисов и первый запуск.
4. Проверку работоспособности с конкретными ожидаемыми результатами.
5. Остановку, обновление, резервное копирование и восстановление.
6. Диагностику известных ошибок.

Для каждой команды указывайте место выполнения: рабочий компьютер или целевой промышленный ПК. Доступ к проверенному стенду — SSH TCP 22, engineer с sudo; значения секретов передаются через окружение, не через файлы.

Для каждой проверенной процедуры указывайте дату, целевой ПК, окружение, версии и фактический результат. Подробные результаты запусков храните локально в `reports/`. Разрушающие команды должны сопровождаться описанием затрагиваемых данных.
