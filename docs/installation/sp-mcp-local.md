# Локальный MCP Смарт Платформы 1.0.0

Процедура выполнена 2026-11-14 на рабочем Mac с Apple Silicon: Docker Desktop
4.49.0 (208700), Engine 28.5.1, Compose v2.40.3-desktop.1, сервер Docker
`linux/arm64`. Смарт Платформа работает на отдельном [установочном стенде](../../inventory/hosts/stand/README.md).
Установка MCP на Ubuntu и работа через LLM-клиенты в этом запуске не проверялись.

Основа — оригинал `input/mcp/DEPLOY_MCP.md`, поставка sp-mcp 1.0.0.
[Замечания и результаты запуска](../review/2026-11-14-mcp-deployment.md) описаны отдельно.
[Идентификаторы поставки](../../inventory/releases/sp-mcp-1.0.0.md) зафиксированы в инвентаре.
Оригиналы поставки не меняются; в отдельном worktree они могут отсутствовать.

## Подготовка образа

Команды выполняются на рабочем компьютере. До загрузки проверьте работающий
Docker и архитектуру его сервера:

```bash
docker version --format '{{.Server.Os}}/{{.Server.Arch}}'
```

Для `linux/arm64` загрузите предоставленный ARM64-архив. Следующая команда
выполняется из корня рабочей копии, в которой есть локальная поставка:

```bash
docker load -i input/mcp/sp-mcp-1.0.0-arm64.tar.gz
docker image inspect smartplatform/sp-mcp:1.0.0 --format '{{.Id}} {{.Os}}/{{.Architecture}}'
```

Для `linux/amd64` поставщик передал отдельный архив; его загрузка и запуск здесь
не проверялись. Сборка образа и загрузка из реестра для проверенного сценария не нужны.

## API-ключ

В веб-интерфейсе платформы откройте учётную запись из списка администраторов
пространства. Проверенный путь: **Профиль → Безопасность → API ключи → Управлять
→ Сгенерировать**. Убедитесь, что созданный ключ включён. В проверенном интерфейсе
администратор пространства отображался с ролью «Интегратор».

Ключ передаётся только через `SP_MCP_API_KEY` в окружении. Не помещайте его в
env-файл, клиентский JSON/TOML, аргументы команд или отчёты. Скрипт запуска умеет
запросить ключ со скрытым вводом в терминале, если переменная ещё не задана.

## Запуск и проверка

Из корня рабочей копии проекта на Mac выполните:

```bash
SP_MCP_URL=http://192.168.10.107:8080 bash scripts/local/start-sp-mcp.sh
```

Скрипт создаёт контейнер `sp-mcp` из уже загруженного образа, передаёт переменные
в Docker по именам и устанавливает `SP_MCP_MODE=facade`, `SP_MCP_WRITE=false`.
Порт публикуется только как `127.0.0.1:8000:8000`; тома и каталоги хоста не
подключаются. Политика контейнера — `unless-stopped`. Существующий контейнер
`sp-mcp` скрипт не заменяет. Compose для этого запуска не используется.

Дождитесь запуска JVM; поставщик указывает 5–15 секунд. Затем проверьте:

```bash
python3 scripts/checks/sp-mcp-http.py
```

Проверка подключается только к `http://127.0.0.1:8000/mcp`, выполняет `initialize`,
`notifications/initialized`, `tools/list`, находит `entity.count` через
`search_tools`, вызывает её для устройств и закрывает MCP-сессию. Тела ответов
и секреты в диагностике ошибок не выводятся. Ожидаются четыре строки `OK`;
число устройств зависит от текущих данных платформы. В выполненном запуске — 9.
Наличие четырёх инструментов само по себе ещё не подтверждает доступ к платформе:
нужен успешный результат `entity.count`.

## Codex

На том же Mac добавьте Streamable HTTP-сервер штатной командой Codex CLI:

```bash
codex mcp add smart-platform --url http://127.0.0.1:8000/mcp
codex mcp get smart-platform
```

Эквивалентная запись в пользовательском `config.toml`:

```toml
[mcp_servers.smart-platform]
url = "http://127.0.0.1:8000/mcp"
```

API-ключ клиенту не нужен: с платформой авторизуется контейнер. В выполненном
запуске запись добавлена в настройки Codex и прочитана обратно через CLI;
`enabled=true`, транспорт `streamable_http`, URL совпал с указанным выше.

Откройте новый чат Codex и попросите: «Используй MCP smart-platform: сколько
устройств на платформе?». Проверьте, что клиент вызывает инструменты сервера.
В текущем чате после изменения настроек инструменты автоматически не появились;
вызов из нового чата пока не проверен.

Параметры подключения описаны в [официальной документации OpenAI](https://developers.openai.com/codex/mcp/).

## Claude Code

На том же Mac в своём терминале выполните:

```bash
claude mcp add --scope user --transport http smart-platform http://127.0.0.1:8000/mcp
claude mcp list
```

В Claude Code откройте `/mcp`, проверьте состояние `smart-platform` и задайте
тот же вопрос о числе устройств. Настройки Claude в этом запуске не менялись,
подключение из Claude Code не выполнялось. Команда приведена по
[официальной документации Claude Code](https://code.claude.com/docs/en/mcp).

Этот URL предназначен для локальных клиентов на том же Mac. Облачный коннектор
claude.ai не обращается к localhost пользовательского компьютера;
[документация Anthropic](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
описывает подключение из облачной сети. У поставки нет собственной входной
HTTP-аутентификации, поэтому публикация этого контейнера в интернет не входит
в проверенную процедуру.

## Границы проверки

Проверены загрузка ARM64-образа, запуск контейнера, HTTP/MCP и реальное чтение
числа устройств. Запись данных, создание дашбордов, нагрузка, остальные
операции каталога и перезагрузка Mac не проверялись. В режиме facade поставщик
заявляет только чтение; переменные режима записи не включались.

Наблюдаемая память после проверки — около 369 MiB; это одиночное измерение,
а не установленное минимальное требование к ресурсам. Перезапуск требует
работающего Docker Desktop и доступа к стенду.
