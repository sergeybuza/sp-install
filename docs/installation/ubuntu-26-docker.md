## Восстановленная история подготовки

**[ПРОВЕРЕНО]** Команды Docker в `.bash_history` пользователя `engineer` не обнаружены; `/root/.bash_history` отсутствует. Последовательность восстановлена по журналу `sudo` и журналу APT, а не по shell history.

**[ПРОВЕРЕНО]** Журнал `sudo` за 2026-11-12 содержит следующую последовательность:

1. `apt update` — три вызова.
2. `apt upgrade`.
3. `apt install -y docker.io docker-compose-plugin` — две попытки.
4. `apt install -y docker.io docker-compose-v2`.
5. `systemctl enable --now docker`.

Наличие команды в журнале `sudo` подтверждает её вызов, но само по себе не подтверждает успешное завершение. Исход и текст ошибок первых попыток с `docker-compose-plugin` не установлены.

**[ПРОВЕРЕНО]** При текущей проверке пакет `docker-compose-plugin` в выводе `apt-cache policy` не отображался; `apt-cache show docker-compose-plugin` завершился с кодом `100` и сообщением `E: No packages found`. Это описывает доступность пакета в настроенных источниках на момент проверки, а не доказывает текст ошибки прошлых попыток.

**[ПРОВЕРЕНО]** В `/var/log/apt/history.log` есть успешно завершённая запись `apt install -y docker.io docker-compose-v2`: начало `2026-11-12 09:35:39`, окончание `09:35:48`. Часовой пояс стенда — `Etc/UTC`; начало соответствует `12:35:39` по Москве.

**[ПРОВЕРЕНО]** Текущая симуляция `apt-get -s install docker.io docker-compose-v2` завершилась с кодом `0`: оба пакета уже последней доступной версии, `0 upgraded, 0 newly installed, 0 to remove and 4 not upgraded`. Симуляция не устанавливала и не обновляла пакеты.

**[ВЫВОД]** Для воспроизведения подтверждённого варианта на Ubuntu 26.04 с такими же репозиториями следует использовать пару пакетов `docker.io` и `docker-compose-v2`. Смешивание этой процедуры с инструкцией для другого источника пакетов требует отдельной проверки.

## Команды для нового ПК

Это предлагаемая процедура по восстановленной истории. Во время текущей проверки стенда команды APT заново **не выполнялись**: рабочая установка уже была готова.

Перед установкой проверьте ОС и наличие существующего Docker. На ПК с действующими контейнерами сначала оцените влияние изменения пакетов на эти сервисы.

Место выполнения: **целевой ПК с Ubuntu 26.04**.

```bash
cat /etc/os-release
uname -m
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
```

Эти команды обновляют индекс пакетов, устанавливают Docker и Compose с зависимостями, запускают Docker и включают запуск службы при загрузке. Docker использует свой каталог данных; на проверенном стенде это `/var/lib/docker`.

`apt upgrade` встречается в восстановленной истории, но не включён в обязательную процедуру: обновление остальных пакетов ОС — отдельное действие с собственным влиянием на ПК. В текущей проверке мы его не выполняли.

## Проверка после установки

Место выполнения: **целевой ПК**.

```bash
sudo systemctl is-active docker
sudo systemctl is-enabled docker
sudo docker version
sudo docker info
sudo docker compose version
sudo docker ps -a
```

Убедитесь, что служба показывает `active` и `enabled`, `docker version` получает сведения как о клиенте, так и о сервере, `docker info` не сообщает об ошибке соединения, а `docker compose version` выводит версию Compose. На новом ПК список контейнеров может быть пустым. На проверенном стенде он был пустым.

Версии из таблицы фиксируют состояние конкретного стенда на дату проверки. Команда `apt install` на другом ПК или позднее может выбрать другие версии из настроенных репозиториев; фактические версии нужно записать после выполнения.

Используйте `sudo` для команд Docker, как в проверенном варианте. Эта процедура не меняет права на `docker.sock` и не добавляет пользователя в группу `docker`.
