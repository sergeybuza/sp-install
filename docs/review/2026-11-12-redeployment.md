# Повторное развёртывание после очистки стенда

Дата: 2026-11-12. Узел `192.168.10.107`, Ubuntu 26.04.1 LTS, linux/amd64,
4 CPU, 14 GiB RAM; до установки свободно 86 GiB. Проверка начата в
14:05:03 UTC / 17:05:03 по Москве, итоговая — в 14:20:32 UTC / 17:20:32
по Москве. Основание: фактически выполненные команды на стенде, сверка
поставки с инвентарём и наблюдение страницы входа в браузере.

## Установка

После предыдущей очистки отсутствовали Docker, его каталоги данных, каталог
платформы, входная поставка и слушатели портов платформы. SSH/sudo и состояние
пакетов проверены. Имевшаяся failed unit `systemd-networkd-wait-online.service`
осталась без изменений; настройки сети не менялись.

После симуляции выполнены `apt-get update`, `apt-get install -y docker.io
docker-compose-v2` и `systemctl enable --now docker`. Транзакция установила
9 пакетов без обновления и удаления остальных. Engine Client/Server 29.1.3,
Compose 2.40.3+ds1-0ubuntu1, Docker active/enabled, overlayfs, cgroup systemd.
`dpkg --audit` и `apt-get check` успешны. Общее обновление ОС не выполнялось.

Архив, CA и Compose переданы на стенд и сверены по SHA-256. Загружены четыре
vendor-образа; все Image ID и архитектуры совпали с инвентарём поставки.
Digest PostgreSQL 16 и Mosquitto 2 также совпали. Vendor-реестр не использовался.
Рабочая конфигурация размещена в `/opt/smart-platform`.

В truststore импортированы 148 стандартных CA и Andromeda CA; проверены alias
и fingerprint Andromeda CA. Выпущен новый MQTT-сертификат с SAN адреса стенда
и localhost, сроком до 2027-11-12. Проверка публичного сертификата успешна;
fingerprint приведён в инвентаре поставки. По разрешению владельца единственный
закрытый ключ расположен на стенде, 0600, UID/GID100:101. Пароли передавались
через окружение, без `.env`, аргументов команд и вывода значений.

Перед установщиком подтверждены схема `smartplatform`, владелец
`smartplatform` и 0 таблиц. Однократный установщик завершился кодом 0 с
маркером `Installation finished successfully!`; после него было 70 базовых
таблиц, после запуска ядра — 73. Контрольный повтор через защитную обёртку
завершился кодом 1 до запуска установщика на непустой схеме.

## Приёмка и повторный запуск

Четыре runtime-контейнера running. PostgreSQL, ядро и UI healthy; у Mosquitto
нет healthcheck. `RestartCount=0`, политика всех контейнеров `unless-stopped`.

`platform-seed-smoke.py` успешно получил HTML `/login`, три локальных ресурса
JS/CSS, выполнил API login и получение пользователя с ролью SYS_ADMIN.

MQTT CONNECT с access token демоустройства получил `CONNACK 0` на 1883 и 8883;
токен оставался только в памяти и окружении. Для 8883 подтверждены TLS 1.3,
доверие публичному `server.crt` и SAN IP `192.168.10.107`. В журнале Mosquitto
найден клиент `sp-monolith`; сырой журнал не выгружался в документацию.

## Изменения процедуры и границы проверки

Создан скилл `.agents/skills/sp-deploy` для новой установки с различением
существующей и частичной установки. Добавлен `scripts/remote/install-database.py`:
он проверяет пустую схему, ограничивает время установщика, захватывает сырой
stdout/stderr только в память и печатает код и наличие маркера успеха.
В командах psql закрыт stdin: при передаче Bash-сценария по SSH Docker CLI
иначе может прочитать последующие строки сценария.

Синтаксис нового Python-скрипта проверен; фактически выполнены успешная
первичная инициализация и отказ на непустой схеме. Локально проверен отказ без
SP_DB_PASSWORD. Скилл прошёл независимую статическую проверку, YAML разобран
Ruby, относительные ссылки проверены. Штатный `quick_validate.py` не запустился:
в локальном Python отсутствует PyYAML. Дополнительные зависимости не
устанавливались. Эти проверки не являются испытанием скилла отдельным агентом
на живом стенде.

Не выполнялись вход обеими ролями через браузер, перезагрузка ПК, сквозная
телеметрия, работа промышленных устройств, сценарии Edge/AI и восстановление
резервных копий. Совпадение пяти счётчиков не доказывает полную целостность БД.
Перед эксплуатацией стоит проверить нужные роли и реальные сценарии устройств.
