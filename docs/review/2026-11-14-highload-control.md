# Приёмка инструмента управления highload

Проверено 2026-11-14 на Mac arm64 с существующим Docker Desktop 4.49.0 /
Engine 28.5.1, Compose v2.40.3-desktop.1, Python 3.14.6. Платформа —
[установочный стенд](../../inventory/hosts/stand/README.md).

Добавлен `./highload`: выбор числа устройств, сигналов и периода, запуск,
остановка, статус и проверка всех активных топиков локального MQTT.
Генерация основана на исходном Excel поставки, отдельным файлом;
поставочные архив, конфигурации и сценарий не изменялись.

## Выполненные проверки

- 13 тестов `python3 -m unittest discover -s tests -v` проверили изоляцию
  Docker-проекта, отклонение повторяющихся топиков и внешних путей,
  обнаружение изменения XLSX после сохранения состояния, сохранение
  остановленного состояния, отсутствие пересоздания на том же уровне,
  возврат к прежнему сценарию при ошибке, очистку неудачной генерации
  и отсутствие токена в argv, JSON состояния и сообщениях ошибок.
- `status` распознал существующие 20×100 с периодом 1000 мс по bind-mount,
  без ручного повторного ввода токена.
- `set 20 100 --period-ms 1000` не изменил ID, время запуска и счётчики
  перезапусков контейнеров.
- `set 10 50 --period-ms 2000` создал и применил XLSX с 500 топиками,
  периодом 2000 мс; `check` получил 1000 сообщений и подтвердил все 500
  топиков. При этом Agent, брокер и MCP сохранили ID и время старта.
- PNG нового сценария просмотрен; в `Period` — 2000, исходное оформление
  сохранено, формулы топиков вычислены, ошибок формул не найдено.
- `stop` остановил все три контейнера highload, сохранив уровень.
- `set 20 100 --period-ms 1000` в остановленном состоянии сохранил выбор,
  оставив контейнеры остановленными.
- `start` запустил 20×100, использовав токен остановленного Agent.
  Agent и брокер сохранили ID, PubMQTT получил нужный сценарий.
- Повторный `set` того же уровня снова не изменил контейнеры.
  Финальный `check` подтвердил 2000 топиков по 4000 сообщениям.
- MCP сохранил ID, время запуска и счётчик перезапусков во всей приёмке;
  его окружение и логи не читались, команды управления им не выполнялись.

## Сквозная проверка после запуска

В **22:51:31 по Москве / 19:51:31 UTC** API платформы подтвердил 20
устройств сценария, на каждом 100 сигналов и 100 статус-кодов. Между двумя
снимками с интервалом 6 секунд обновились временные метки всех 2000
сигналов; максимальный возраст точек во втором снимке — 3368 мс.
В тенанте осталось 30 устройств. Значения телеметрии и секреты в отчёты
не записывались. Нагрузка оставлена включённой: **20×100, период 1000 мс**.

`check` самой утилиты ограничен локальным MQTT. Описанная проверка API
выполнена отдельно; для неё пароль и API-токен находились только в памяти
и окружении процесса. Уменьшение сценария не удаляет старые устройства
и сохранённые ключи в платформе.

Локальные результаты: `reports/highload-mac/control-20261114/`.
Не выполнялись длительный стресс, отказ Docker в середине операции,
перезагрузка Mac, сон и определение предельной производительности.
Возврат при ошибке применения проверен тестом с имитацией отказа;
реальный отказ брокера/платформы намеренно не создавался.
