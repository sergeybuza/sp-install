# Пробный highload с Mac на стенд

Дата: 2026-11-14. Генерация на Mac: macOS 26.5.2, arm64, 8 CPU, 16 GiB RAM.
Docker Desktop 4.49.0, Engine 28.5.1 linux/arm64,
Compose v2.40.3-desktop.1; VM — 8 CPU и около 7,65 GiB RAM.
Целевая платформа — [установочный стенд](../../inventory/hosts/stand/README.md).
ОС и Docker стенда в этом запуске повторно не проверялись.

Шлюз создан **21:50:44 по Москве / 18:50:44 UTC**.
Итоговая проверка телеметрии — **21:52:19 по Москве / 18:52:19 UTC**.
Поток после проверки оставлен включённым.

## Запуск и результат

- Контрольные суммы двух файлов совпали с оригиналами;
  [инвентарь](../../inventory/releases/highload-2026-11-14.md) содержит состав и идентификаторы.
- Два готовых образа загружены без сборки; все три используемых образа
  имеют архитектуру linux/arm64. Обращений к реестрам образов не было.
- Брокер стенда на 1884 принял MQTT 3.1.1 CONNECT без логина и пароля.
- Вход администратора тенанта и роль TENANT_ADMIN подтверждены через API.
  Использованы учётные данные поставки из разрешённой таблицы документации;
  пароли и API-токены не сохранялись в файлы и не выводились.
- Методы создания устройства и чтения credentials/телеметрии проверены
  по OpenAPI самого стенда. Признак `additionalInfo.gateway` подтверждён
  по его UI-модулям `DeviceDetailsForm` и `device.model`.
- Создан отдельный шлюз `highload-mac-20261114`, профиль `default`.
  До публикации проверено отсутствие конфликтов имён десяти устройств
  сценария с девятью существовавшими устройствами тенанта.
- `config --quiet` и `up --wait --wait-timeout 60 --pull never` завершились
  кодом 0. Три контейнера работают, Mosquitto healthy; у Agent нет healthcheck.
- Локальная подписка получила пять сообщений сигналов. Подписчик брокера
  стенда получил четыре начальных сообщения Agent — версии, атрибутов
  и подключения устройств. Дальнейшее сохранение сигналов проверено через API.
- Платформа создала все десять устройств стандартного сценария. Всего
  в тенанте стало 20 устройств: исходные девять, шлюз и десять дочерних.
- На каждом дочернем устройстве API вернул 10 сигналов и 10 полей
  `_status_code`: суммарно 100 + 100 ключей. Ответ DEVICE содержит
  `timeseries` и `metadata`; телеметрия находится на дочерних устройствах.
- В двух снимках с интервалом 5 секунд максимальные временные метки каждого
  из десяти устройств продвинулись на 4996–4997 мс. Возраст последних
  точек на втором снимке — 1136–1137 мс. История одного сигнала за последние
  30 секунд содержала 29 точек.
- В момент измерения RAM Mosquitto/Agent/PubMQTT — 12,85/23,71/13,14 MiB;
  CPU — 1,65/0,52/0,74%. Это отдельный снимок, не длительное измерение.

Highload использует только проект `sp-highload-mac` и собственную сеть;
портов на Mac не публикует. Существующий MCP-контейнер на
`127.0.0.1:8000` оставался running; команды управления им не выполнялись.
Функциональность MCP не проверялась.

## Секреты и конфигурация Agent

Оригиналы поставки не изменялись. Поставочный `.env` не извлекался.
Вместо исходного entrypoint используется отдельная оболочка: токен
поступает из окружения, YAML передаётся Agent через pipe `/dev/stdin`.
Корневая ФС Agent read-only, SQLite — в tmpfs; постоянные Docker-логи
Agent отключены. На работающем контейнере проверено отсутствие токена
в argv и его буквального значения в текущих файлах SQLite-буфера.
Проверка буфера относится только к наблюдавшемуся содержимому.

Одноразовый тест чтения stdin сначала получил пустой поток из-за отсутствия
`docker run -i`; после исправления конфигурация принята. Тест оболочки
сначала обнаружил ограничение длины токена (20 символов), затем прошёл
с допустимым фиктивным значением. Изолированные тесты не имели сети и
постоянных логов. Agent при ошибке валидации возвращает код 0, поэтому
код завершения и Compose running сами по себе недостаточны для приёмки.

Первое чтение DEVICE timeseries ошибочно учитывало поля внешнего конверта
как ключи телеметрии. После чтения схемы и реального ответа проверка
исправлена на `timeseries` и повторена для всех десяти устройств.
Проверка argv через `docker top` сначала завершилась ошибкой из-за
отсутствия колонки PID; с `-eo pid,args` выполнена успешно.
Офлайн `go tool nm` недоступен; дизассемблирование не выполнялось.

## Границы проверки

Проверен пробный поток около 100 публикаций/с по Excel-сценарию, а не
предельная производительность платформы. Скорость записи БД отдельно
не измерялась. Не выполнялись длительный прогон, повышение нагрузки,
отказ сети, перезагрузка Docker Desktop/Mac, проверка сна и восстановление
буфера. SQLite в tmpfs теряется при остановке.

HTTP `/` на 8080 вернул 200 HTML; `/login` — 404. API авторизации и
телеметрии на том же порту работали. Вход через браузер и исправление
маршрута `/login` не выполнялись; прежний `platform-http.py`, требующий
200 на `/login`, в этом запуске не запускался.

Локальный отчёт: `reports/highload-mac/20261114T184023Z/`, исключён из Git.
Там находятся идентификаторы тестовых устройств и санитизированные
результаты двух снимков; значений телеметрии и токенов в отчёте нет.
Команды запуска и остановки — в [инструкции](../installation/highload-mac.md).
