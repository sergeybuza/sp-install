# Проверка поставки sp-mcp 1.0.0 от 2026-11-14

Исходный документ — `input/mcp/DEPLOY_MCP.md`; исходные образы —
`sp-mcp-1.0.0-arm64.tar.gz` и `sp-mcp-1.0.0-amd64.tar.gz` в той же локальной
поставке. Документ и архивы не редактировались. В этом запуске использован
только ARM64-образ; основной checkout содержит поставку, а отдельный worktree —
подготовленные скрипты и документацию.

## Замечания к инструкции

| Раздел | Проблема | Основание и решение |
| --- | --- | --- |
| «Правила для агента», шаг 3, примеры клиентов | Предписано сохранять API-ключ в env-файле | Это противоречит AGENTS.md проекта. В проверенном запуске ключ передан через окружение; запускатель запрашивает его без эха, если env ещё не задан. Секретный файл не создаётся. |
| Шаг 3, создание ключа | Путь указан как «Профиль → API keys → +» | В UI платформы 2.0.0 найден путь «Профиль → Безопасность → API ключи → Управлять → Сгенерировать». Ключ создан владельцем для администратора пространства; чтение через MCP прошло. |
| Шаг 4, проверка STDIO | Описана проверка STDIO | В этой задаче выбран Streamable HTTP для общего сервера Codex и Claude Code. STDIO отдельно не запускался; HTTP проверен настоящими MCP-запросами и чтением платформы. |
| Вводная и «Ограничения» | Вводная заявляет отсутствие записи, ниже упоминается SP_MCP_WRITE в режиме flat | Запись не проверялась. Проверенный запуск использует facade и явно задаёт SP_MCP_WRITE=false. Создание дашбордов из этого результата не следует. |

## Фактически выполненный запуск

- Рабочий компьютер: Mac Apple Silicon, Docker Desktop 4.49.0 (208700),
  Docker Engine 28.5.1, Compose v2.40.3-desktop.1, `linux/arm64`.
- SHA-256 ARM64-архива:
  `e3f48b1c7f5a1fa3af46d0b9efea25821b8e7f997b2f8225d37236ed92b6d1df`.
- Загруженный тег: `smartplatform/sp-mcp:1.0.0`; Docker Image ID:
  `sha256:a72101bcbc71d61d3c2802bee76c413713e2565beed6339a7f0895a43658f454`.
- Контейнер `sp-mcp`: running, RestartCount=0, `unless-stopped`,
  `127.0.0.1:8000:8000`, без томов и bind mounts. Размер образа в Docker —
  409231427 байт. После проверки наблюдалась память 368.5 MiB.
- Платформа — существующий установочный стенд; её контейнеры и данные не
  изменялись командами развёртывания MCP.
- `initialize`: HTTP 200, сервер `smart-platform-mcp 1.0.0`, протокол
  `2025-06-18`, заголовок `Mcp-Session-Id` получен.
- `notifications/initialized`: HTTP 202; `tools/list`: HTTP 200 и инструменты
  `search_tools`, `call_tool`, `run`, `get_result`.
- `search_tools` нашёл карточку `entity.count`; `call_tool` с
  `{"name":"entity.count","args":{"type":"device"}}` вернул 9.
  Первый ответ содержал время `2026-11-14T21:32:51.690651009+03:00`.
- Сессии закрыты через DELETE `/mcp`, HTTP 200. Повторяемая проверка
  `scripts/checks/sp-mcp-http.py` завершилась кодом 0 и тем же числом устройств.
- Запускатель прошёл `bash -n`, остановился с кодом 1 без SP_MCP_URL и
  успешно создал реальный контейнер после скрытого ввода ключа.
- Сервер добавлен в пользовательские настройки Codex через `codex mcp add`.
  Обратное чтение CLI подтвердило включённый Streamable HTTP на локальном URL
  без учётных данных в настройках клиента. Вызов инструмента самой моделью
  ещё не проверен. Для Claude Code подготовлена инструкция; его настройки
  по решению владельца не менялись.

Подробный обезличенный отчёт сохранён локально в
`reports/mcp-mac-arm64-20261114/preflight-and-smoke.json`, исключённом из Git.
Невыполненные проверки: LLM-вызов из клиентов, STDIO, AMD64, запись и создание
дашбордов, нагрузочные сценарии, остальные методы каталога, перезагрузка Mac.
Процедура и команды — в [инструкции локального MCP](../installation/sp-mcp-local.md).
