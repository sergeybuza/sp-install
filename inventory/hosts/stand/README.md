## Пробный highload 2026-11-14

В 21:50 по Москве создан отдельный шлюз `highload-mac-20261114`.
Генератор запущен на Mac в отдельном Compose-проекте и отправляет данные
в брокер стенда на 1884. На стенде контейнеры не развёртывались и не
перезапускались в рамках этого запуска.

К 21:52:19 по Москве API подтвердил 10 дочерних устройств, 100 сигналов
и 100 полей статус-кодов, продвижение временных меток и историю одного
сигнала. В тенанте стало 20 устройств (ранее 9). Поток оставлен включённым.
HTTP `/` на 8080 — 200, `/login` — 404; API авторизации и телеметрии
работают. ОС, Docker и состояние контейнеров самого стенда повторно
не проверялись. [Результаты и ограничения](../../../docs/review/2026-11-14-highload-mac.md),
[инструкция генератора](../../../docs/installation/highload-mac.md).

## Последняя установка 2026-11-12

2026-11-12 после последней очистки заново установлены Docker и Смарт Платформа
2.0.0 по монолитной инструкции. Итоговая проверка сервисов:
**18:51:30 по Москве / 15:51:30 UTC**.

- Docker Engine 29.1.3 и Compose 2.40.3 установлены из репозиториев Ubuntu;
  Docker active/enabled. Транзакция установила 9 пакетов без обновлений и удалений.
- Архив, конфигурация, Image ID и digest совпали с инвентарём. Новая пустая
  схема инициализирована однократно, установщик завершился кодом 0 с маркером успеха.
- Четыре runtime-контейнера running; PostgreSQL, ядро и UI healthy, Mosquitto
  без healthcheck. RestartCount=0, политика unless-stopped.
- До и после штатного stop/up прошли UI/API-проверки SYS_ADMIN и MQTT TLS 1.3
  с проверкой сертификата и IP. Счётчики tenant/sp_user/device/dashboard/rule_chain
  сохранились: 1/6/9/4/3, базовых таблиц — 73.
- В браузере видна форма входа [http://192.168.10.107:8080/login](http://192.168.10.107:8080/login).
  Вход через браузер, MQTT CONNECT, перезагрузка ПК и промышленные сценарии
  в этом запуске не проверялись.
- Выпущен новый MQTT-сертификат; fingerprint и срок приведены в
  [инвентаре поставки](../../releases/smart-platform-2.0.0.md). Единственный
  закрытый ключ хранится на стенде в согласованном пути, 0600, UID/GID 100:101.
- `dpkg --audit` и `apt-get check` успешны. Имевшаяся до установки failed unit
  `systemd-networkd-wait-online.service` сохраняется; отдельно не исправлялась.
