# Установочный стенд

Назначение — установка и проверка монолитной Смарт Платформы. Последняя установка проверена 2026-11-12; ОС, ресурсы, SSH и Docker CLI перепроверены 2026-11-14 при ступенчатом highload. Отдельные проверки UI/чтения через MCP и пробного потока также выполнены 2026-11-14. Даты относятся к наблюдениям и не гарантируют текущую доступность. Список стендов — в [справочнике](../README.md).

## Проверка доступа через MCP 2026-11-14

С рабочего Mac открыта форма входа платформы, выполнен вход в UI и переход в
контекст администратора пространства. Владелец создал API-ключ; локальный
MCP `smart-platform-mcp 1.0.0` через `entity.count` прочитал 9 устройств.
SSH, версии и состояние сервисов Ubuntu в этом запуске не проверялись.
Подробности и границы — в [отчёте о MCP](../../../docs/review/2026-11-14-mcp-deployment.md).

## Пробный highload 2026-11-14

В 21:50 по Москве создан отдельный шлюз `highload-mac-20261114`.
Генератор запущен на Mac в отдельном Compose-проекте и отправляет данные
в брокер стенда на 1884. На стенде контейнеры не развёртывались и не
перезапускались в рамках этого запуска.

К 21:52:19 по Москве API подтвердил 10 дочерних устройств, 100 сигналов
и 100 полей статус-кодов, продвижение временных меток и историю одного
сигнала. В тенанте стало 20 устройств (ранее 9). Поток оставлен включённым.
HTTP `/` на 8080 — 200, `/login` — 404; API авторизации и телеметрии
работают. ОС, Docker и состояние контейнеров самого стенда повторно
не проверялись. [Результаты и ограничения](../../../docs/review/2026-11-14-highload-mac.md),
[инструкция генератора](../../../docs/installation/highload-mac.md).

### Проверки 20×100 до ступенчатого теста

2026-11-14 к 22:33:03 по Москве генератор на Mac переключён на 20 устройств
по 100 сигналов с периодом 1000 мс. API подтвердил 2000 сигналов и 2000
полей статус-кодов; между снимками с интервалом 10 секунд продвинулись
временные метки всех 2000 сигналов. Максимальный возраст последних точек
на втором снимке — 2758 мс. Всего в тенанте 30 устройств.

Пересоздан только PubMQTT на Mac; идентификаторы Agent, локального брокера
и MCP не изменились. Поток оставлен включённым. Подробности — в локальном отчёте
`reports/highload-mac/20x100-20261114/report.md`; длительный прогон на этом
уровне не проверялся.

В 22:51:31 по Москве повторно подтверждены все 2000 обновляющихся сигналов
после проверки нового инструмента `./highload`: смена уровня, периода,
stop/start и повторный выбор того же уровня. В ходе приёмки highload
останавливался и запускался; MCP сохранил ID и время старта. Итог — 20×100,
период 1000 мс. [Приёмка инструмента](../../../docs/review/2026-11-14-highload-control.md).

### Ступенчатый тест 30×150 и 40×200

2026-11-14 проверен SSH alias `irobo` на Mac: неинтерактивный вход
`BatchMode=yes` на `engineer@192.168.10.107:22` успешен. Заново прочитаны
Ubuntu 26.04.1 LTS / x86_64, 4 CPU, 15 985 901 568 байт RAM (14,89 GiB),
около 4 GiB swap, Docker CLI 29.1.3 и active у службы Docker. Версии
runtime-образов и здоровье каждого контейнера платформы не перепроверялись.

При периоде сигналов 1000 мс ступень 30×150 завершена за 590,391 секунды
с CPU max 44,60%; свежие данные всех 4500 сигналов подтверждены API.
На 40×200 в **23:56:46,442 по Москве** CPU достиг **65,23%**. Ступень
прервана через 108,087 секунды, затем остановлены все три контейнера
highload на Mac. API подтвердил свежие данные всех 8000 выбранных ключей
и продвижение контрольных сигналов всех 40 устройств. RAM max — 17,52%,
swap 0. Более высокие ступени не запускались.

После остановки CPU — 3,03%, RAM — 17,42%, HTTP `/` — 200; API доступен.
В платформе осталось 40 тестовых устройств и 50 устройств всего. Доступное
место на разделе платформы — около 76,67 GiB. Данные не удалялись,
контейнеры платформы не перезапускались. Последнее состояние генератора —
**остановлен, выбран 40×200**. Подробные условия и ограничения —
в [результатах теста](../../../docs/review/2026-11-14-highload-staircase.md),
локальные материалы — `reports/stand-192.168.10.107/20261114T204435Z-highload/`.

## Последняя установка 2026-11-12

2026-11-12 после последней очистки заново установлены Docker и Смарт Платформа
2.0.0 по монолитной инструкции. Итоговая проверка сервисов:
**18:51:30 по Москве / 15:51:30 UTC**.

- Docker Engine 29.1.3 и Compose 2.40.3 установлены из репозиториев Ubuntu;
  Docker active/enabled. Транзакция установила 9 пакетов без обновлений и удалений.
- Архив, конфигурация, Image ID и digest совпали с инвентарём. Новая пустая
  схема инициализирована однократно, установщик завершился кодом 0 с маркером успеха.
- Четыре runtime-контейнера running; PostgreSQL, ядро и UI healthy, Mosquitto
  без healthcheck. RestartCount=0, политика unless-stopped.
- До и после штатного stop/up прошли UI/API-проверки SYS_ADMIN и MQTT TLS 1.3
  с проверкой сертификата и IP. Счётчики tenant/sp_user/device/dashboard/rule_chain
  сохранились: 1/6/9/4/3, базовых таблиц — 73.
- В браузере видна форма входа [http://192.168.10.107:8080/login](http://192.168.10.107:8080/login).
  Вход через браузер, MQTT CONNECT, перезагрузка ПК и промышленные сценарии
  в этом запуске не проверялись.
- Выпущен новый MQTT-сертификат; fingerprint и срок приведены в
  [инвентаре поставки](../../releases/smart-platform-2.0.0.md). Единственный
  закрытый ключ хранится на стенде в согласованном пути, 0600, UID/GID 100:101.
- `dpkg --audit` и `apt-get check` успешны. Имевшаяся до установки failed unit
  `systemd-networkd-wait-online.service` сохраняется; отдельно не исправлялась.
