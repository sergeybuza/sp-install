# Скрипты

Скрипты подготовки, установки и проверки добавляются после подтверждения требований поставки.

[local/highload.py](local/highload.py) вызывается через `./highload` из корня
рабочей копии Mac. Команды `set`, `start`, `stop`, `status`, `check` управляют
только проектом `sp-highload-mac`, сохраняют выбранный уровень без секретов
и проверяют топики локального MQTT. Генератор
[generate-highload-scenario.mjs](local/generate-highload-scenario.mjs) принимает
`--devices`, `--signals`, `--period-ms`, создаёт отдельный XLSX и сохраняет
оригинал поставки. [Порядок работы и границы проверки](../docs/installation/highload-mac.md#быстрое-управление-нагрузкой).

[local/start-sp-mcp.sh](local/start-sp-mcp.sh) запускает на рабочем компьютере уже загруженный `smartplatform/sp-mcp:1.0.0`: Streamable HTTP на `127.0.0.1:8000`, режим facade, запись выключена. Требует `SP_MCP_URL`; ключ получает из `SP_MCP_API_KEY` либо запрашивает со скрытым вводом в терминале. Env-файл не создаёт, существующий контейнер не заменяет. На Mac ARM64 проверен реальный запуск.

[checks/sp-mcp-http.py](checks/sp-mcp-http.py) проверяет локальный MCP на `127.0.0.1:8000`: handshake, четыре инструмента facade, поиск и вызов `entity.count`, затем закрытие сессии. На Mac проверено чтение 9 устройств. Скрипт не получает API-ключ, работает через уже запущенный MCP. Процедура и границы — в [инструкции MCP](../docs/installation/sp-mcp-local.md).

[remote/install-database.py](remote/install-database.py) выполняется на целевом ПК после подготовки PostgreSQL. Требует `SP_DB_PASSWORD` в окружении и `/opt/smart-platform/compose/monolith.yml`; проверяет схему, владельца и отсутствие таблиц, однократно запускает установщик. Его stdout/stderr остаются в памяти: скрипт печатает только код и наличие маркера успеха. Непустая схема блокирует повторный запуск. При тайм-ауте нужно проверить контейнер и БД, поскольку установщик мог продолжить работу.

[checks/platform-http.py](checks/platform-http.py) проверяет HTTP/HTTPS, HTML и локальные JS/CSS, вход администратора и ответ API пользователя. При HTTPS проверяется сертификат; для самоподписанного сервера передаётся публичный `--ca-cert`. Пароль берётся только из `SP_ADMIN_PASSWORD`, логин — из `SP_ADMIN_USERNAME`. Токены и ответы API не печатаются, внешние перенаправления запрещены. На стенде проверены HTTP8080, три ресурса UI и авторизация SYS_ADMIN, в том числе после перезапуска.

[checks/platform-seed-smoke.py](checks/platform-seed-smoke.py) запускает ту же проверку **на стенде с доступом к Docker**. Если пароль не задан в env, он читает JAR установленного контейнера в память и проверяет точную структуру метода создания начального администратора 2.0.0. Начальный пароль поступает сразу в env, без файлов и вывода. После смены пароля нужен `SP_ADMIN_PASSWORD`; скрипт не меняет учётные записи и не выполняет сброс. Полный запуск на стенде прошёл до и после перезапуска.

Команды и подготовка окружения приведены в [инструкции установки](../docs/installation/smart-platform-2.0.0.md). Пароли не передаются аргументами CLI и не сохраняются в `.env`.

[local/highload-agent-entrypoint.sh](local/highload-agent-entrypoint.sh)
монтируется из Mac в контейнер Agent и выполняется внутри него. Он получает
токен и адреса из окружения, формирует конфигурацию в pipe и передаёт её
через `/dev/stdin`, без YAML с секретом и без токена в argv. Используется
только [отдельным Compose highload](../deploy/compose/highload-mac.yml);
[проверенный запуск](../docs/installation/highload-mac.md) описан отдельно.

- `local/` — выполняются на рабочем компьютере: подготовка, передача поставки по локальной сети, управление установкой.
- `remote/` — выполняются на целевом промышленном ПК: подготовка Ubuntu и развёртывание платформы.
- `checks/` — проверяют готовность окружения и работоспособность платформы; каждый скрипт должен явно указывать место выполнения.

Указывайте назначение, поддерживаемое окружение, необходимые права и затрагиваемые пути. Проверяйте входные параметры; повторный запуск должен быть предсказуемым. Изменения данных и системных настроек описывайте до команды запуска.
